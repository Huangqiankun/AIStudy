## 1. 建立概念：是什么，为什么需要

**本课只回答**：稠密与稀疏检索给出不同量纲、不同顺序的结果时，怎样合成一个候选池；为什么融合之后仍可能需要重排？

**类比**：把稀疏和稠密检索看成 Android 中两个独立的数据源：一个像按精确字段查询本地数据库，另一个像按语义相似度返回远端搜索结果。两边的“分数”由不同规则产生，不能像同一单位的数值那样直接相加。RRF 更像只根据各数据源内部名次合并候选；重排则像候选合并后，再用一个更贵但更细的统一比较器逐项比较。类比只说明阶段职责，不表示 RRF 或交叉编码器等同于 Android 的某个具体 API。

```text
查询 ─┬─→ BM25：词项匹配分数 ─┐
      │                       ├─→ RRF：按各路名次合并候选 ─→ 重排器：统一逐对精排 ─→ top-k
      └─→ Dense：余弦相似度 ──┘

      两路原始分数量纲不同          融合负责“汇总候选”          重排负责“重新判断相关性”
```

**实验全景预告**（只说明路线，不揭示结果）：

- 要完成的任务：让同一组带人工标注的查询同时经过 BM25、稠密检索、RRF 和归一化加权融合，逐阶段比较候选与指标。
- 学员会亲自运行：先跑关闭神经重排的完整双路检索基线；再用一组受控排名，只改变一个候选的原始分数、保持两路名次不变，比较两种融合算法。
- 会得到的产物：控制台阶段表、`%TEMP%\aistudy-d27-hybrid\lesson-d27-hybrid.json`，以及受控融合探针的两组 JSON 排名。
- 结束时要能回答：为什么不能直接比较 BM25 与余弦原始分数，RRF 实际读取什么，融合与重排各自能改变什么、不能补回什么。

**确认问题**：如果 BM25 的第一名得分是 `12`，稠密检索的第一名余弦相似度是 `0.82`，仅凭 `12 > 0.82`，能否断定 BM25 的候选更相关？先说结论和理由。

**学员回答（2026-11-12）**：不能；两个分数不是同一种“单位”，不能直接比较。机制边界正确：这是跨检索器原始分数量纲不可直接比较的判断，还不是本次实验的实测结果。

## 2. 实验前预测

- 任务与输入：教材内置英文语料与查询集，含精确型号/错误码和无词面重叠的语义改写；人工 `expected` 指定相关文档。
- 固定条件：同一语料、查询、MiniLM 模型、分块、每路 `top_k=5`、`eval_k=3`，关闭神经重排以隔离观察召回和融合。
- 观察点：同一查询在 `sparse`、`dense`、`rrf`、`weighted` 四个阶段的候选顺序、分数和指标。
- 预测问题：两路各有擅长与失手的查询时，合并后的指标和单路相比可能怎样变化？理由必须落在候选是否进入、各路名次和融合规则上，不能预设一定提升。
- 学员预测（2026-11-12）：无法确定；初始理由认为两路各自遗漏不同查询，结果可能受“运气”影响。讲师校准为可验证假设：固定输入、模型和参数时运行未必随机；当前无法确定，是因为尚不知道两路候选的互补程度、相关文档在各路的实际名次，以及融合后是否进入 `top-3`。RRF 也不选择某一路的“最高原始分数”，而是依据各路名次累计贡献。

**真实证据（学员运行，2026-11-12）**：模型权重成功从本地缓存加载；20 篇文档被切成 22 个 chunk，评测 12 条查询，`top_k=5`、`eval_k=3`、CPU、神经重排禁用。阶段汇总为：BM25 `Recall@3=0.8333 / MRR=0.7917 / nDCG@3=0.8026`；Dense `1.0000 / 0.9167 / 0.9385`；Hybrid-RRF `1.0000 / 1.0000 / 1.0000`；Hybrid-Weighted `1.0000 / 0.9583 / 0.9692`。收据写入 `%TEMP%\aistudy-d27-hybrid\lesson-d27-hybrid.json`。

**学员对汇总表的解释（2026-11-12）**：RRF 把已经找到但靠后的正确文档提升到第一名；没有增加前三名内找到的相关文档，因为 Dense 的 Recall@3 已为 100%。方向正确。术语校准：这里提升的是首个相关文档名次和 MRR，不笼统称为“准确率”；在本数据集每条查询只有一个 `expected` 的前提下，Recall@3=1 表示每条查询的相关文档都已进入前三，并非一般意义上的文档数量指标。

## 7. 理解检查：每次只问一题

1. **概念复述**：RRF 为什么能避开 BM25 与余弦分数量纲不同的问题？它牺牲了什么信息？
2. **结果预测**：保持两路名次不变，只改变一个原始分数，RRF 与归一化加权融合各可能怎样变化？
3. **故障定位**：目标文档不在重排输入池里，应先查重排模型、融合结果，还是两路召回？分别需要什么证据？

<details><summary>讲师核对要点（学员回答后再展开）</summary>

1. RRF 使用路内排名而不是跨路比较原始分数；因此不受原始量纲直接影响，但丢弃分数差距信息。
2. RRF 只要名次与权重不变就不受原始分数变化影响；归一化加权融合会保留路内相对分数间距，结果分值乃至次序都可能变化。
3. 先查重排输入池的直接证据，再沿 RRF 候选回溯两路召回；候选缺失时不能仅调重排器，需区分召回缺失与融合截断。

</details>
